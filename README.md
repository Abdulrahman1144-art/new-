# UAE Cancer Dataset: Outcome Status Explorer

An educational end-to-end data science project that cleans a supplied UAE cancer
workbook, explores it, compares classifiers, tunes a baseline model, and serves
an exploratory prediction through Streamlit.

## Business question

Can diagnosis-time attributes classify the **recorded `Outcome` label** in this
workbook? The exploratory objective is to establish a reproducible baseline and
surface data quality/provenance requirements for a future, properly sourced
analysis. This is not a survival model, treatment-effect estimate, diagnosis
tool, or clinical risk score. The observation time for `Outcome` is unspecified.

## Dataset, license, and limits

The supplied `uae_cancer_dataset_200k.xlsx` contains 200,000 rows and 20 columns.
Its original source, license, generation method, and collection protocol were
not supplied. It must not be represented as verified real-world UAE patient
data. Obtain written instructor approval if it is synthetic and confirm rights
before sharing or public deployment. See [dataset search log](docs/dataset_search_log.md)
and [data dictionary/quality notes](docs/data_dictionary.md).

Put the workbook at `data/raw/uae_cancer_dataset_200k.xlsx`, or set
`CANCER_DATA_PATH` to its path. Data is excluded from Git by `.gitignore`.

## Run locally

Python 3.10–3.13 is recommended for broad package compatibility.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:CANCER_DATA_PATH = "C:\path\to\uae_cancer_dataset_200k.xlsx"
python train.py
python -m streamlit run app.py
```

The pipeline makes a stratified 80/20 split, compares logistic regression and a
decision tree, tunes logistic regression with 3-fold randomized search, and
writes a cleaned table to `data/processed/cleaned_dataset.csv`, a model artifact,
and metrics to `reports/model_metrics.json`. These runtime artifacts are
committed for deployment. Preprocessing is fitted inside the model pipeline to avoid leakage.
Missing comorbidity becomes `Unknown`;
patient ID, treatment/follow-up details, dates, hospital, physician, weight and
height are excluded from predictors. BMI is derived from weight/height.

## Deployment

Streamlit Community Cloud can use `app.py`, `requirements.txt`, and the
committed files under `data/processed/`, `models/`, and `reports/`. Before
using a public deployment, confirm data-sharing rights: the dataset source and
license are unverified, and the CSV contains patient-level fields. Never
publish identifiable or restricted health data without authorization.

The repository also contains `index.html` and `dashboard-worker.js` for GitHub
Pages. The static page loads `data/processed/cleaned_dataset.csv` in the browser,
so its filters and charts update without a Python server. GitHub Pages still
cannot execute `app.py`; use Streamlit Community Cloud for the Streamlit
version. To publish the static page, configure **Settings → Pages → Deploy
from a branch → `main` → `/(root)`**. The browser-side prediction form uses the
fitted model parameters. Its scores are exploratory dataset-label probabilities,
not clinical risks.

## Results

The benchmark report and score values are generated by `python train.py` and
stored locally in `reports/model_metrics.json`; scores should be interpreted
only as fit to these supplied labels. No results are claimed until the pipeline
has run on the workbook.
